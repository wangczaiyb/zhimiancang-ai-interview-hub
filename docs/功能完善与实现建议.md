# 功能模块完善与实现建议

> 本文档基于当前代码库（`ai-interview-hub`，Vue 3 + Element Plus 前端 / FastAPI + SQLAlchemy 后端）的现状盘点，列出尚需完善或未实现的功能模块，并给出实现建议与优先级。
> 优先级约定：**P0** = 功能断裂/安全隐患（必须修）；**P1** = 功能补全（影响体验闭环）；**P2** = 平台化与工程化（稳定后推进）。
> 已完成的功能模块已移至 [update_log.md](./update_log.md)（含第 1、2、2.5 批：账号安全、能力诊断与岗位匹配真实化、消息推送与会话落库、模拟面试题库与组卷引擎等）。

---

## 一、总体结论

- **核心短板集中在**：① 企业/管理端统计指标仍有写死项；② 参照 `report.html` 的会话状态机、超时处理、匹配度排行榜、AI 通道可观测等尚未落地（见第 3.5 批）；③ 平台缺少**缓存、限流、异步任务、监控**等基础能力。

---

## 二、企业招聘端

### 2.1 招聘数据分析（P1）
- `backend/app/api/v1/enterprise.py` 的 `get_analytics` 存在写死指标（如 `interview_rate: 65`），未从真实 `Application`/`Interview` 聚合。
  - 建议：全部指标改由 `Application` 状态分布、`Interview` 完成率、`CompanyMember` 招聘效率实时计算。

---

## 三、平台管理端

### 3.1 AI 服务监控（P1）
- `backend/app/api/v1/admin.py` 的 `get_ai_providers` 写死 `success_rate: 99.8` 等指标。
  - 建议：从 `ResumeAIAnalysis` / `AnswerEvaluation` / `OperationLog` 真实统计调用量与成功率；`AI Provider` 增加每次调用的 token 用量与耗时记录，便于成本核算。

---

## 四、模拟面试补强项（参照 `docs/report.html` 对比，P1~P2）

1. **会话状态机与非法迁移拦截**：当前 `start/finish` 直接赋值 status，无前置校验；重复提交同题会静默覆盖重评、结算后仍可提交、无"中止面试"端点。建议集中声明迁移规则（非法迁移返回 409），新增 abort 端点。
2. **逐题倒计时服务端超时处理**：`time_limit_sec` 已下发前端计时，但服务端不校验超时。建议超时作答给出标记与轻扣分（不归零），空作答得 0 分并提示。
3. **候选人匹配度排行榜**：`/enterprise/candidates` 已算出 `match_score` 但按 `Application.id desc` 排序。建议提供按匹配度排序的榜单视图 + 成绩段分布。
4. **AI 评分通道可观测**：`AICallLog` 表已定义但全库零写入点。建议 provider 每次调用落库（业务类型/耗时/状态/降级原因），新增 `GET /ai/channel` 类接口暴露当前通道与降级状态。
5. **假字段治理**：`InterviewAnswer.speaking_rate/filler_count` 为前端默认值、`audio_file_id` 无写入链路、`/personal/growth` 与报告接口存在无数据时写死兜底。建议要么接入真实语音分析，要么删除/返回空态，避免误导。

---

## 五、平台基础能力与工程化（P2）

1. **缓存与限流缺失**：`config.py` 中 `REDIS_URL` 仅在 `.env.example` 注释存在、未在 Settings 声明，无任何限流中间件。建议接入 Redis 缓存 + 接口级速率限制（登录/注册/AI 接口优先）。
2. **AI 同步阻塞**：简历诊断/面试出题/学习路线生成均为**同步阻塞式**调用（`await` 在请求线程内），高并发下易超时。建议引入异步任务队列（Celery / RQ / FastAPI BackgroundTasks）+ 前端轮询/推送。
3. **登录安全**：无验证码、无登录失败锁定、无设备指纹。建议至少加登录与注册的图形验证码与失败次数限流。
4. **文件安全**：`files.py` 仅校验扩展名与 10MB，未校验真实 MIME / 未做内容脱敏；`MAX_UPLOAD_SIZE_MB` 未在 Settings 声明，大小写死。建议：声明配置项、按 content-type 白名单 + 魔数校验、接入病毒扫描。
5. **邮箱/手机验证缺失**：注册与找回密码均无 `email_verified` / `phone_verified` 字段与验证流程。
6. **告警与监控**：无 `/health`、无 metrics/Prometheus 埋点、AI 调用异常仅靠日志。建议补充健康检查与关键业务指标埋点。
7. **测试覆盖不足**：`backend/tests/test_backend.py` 存在但环境未安装 `pytest`，缺少端到端与回归用例。建议补齐 `pytest`/`httpx` 依赖并建立 AI mock 模式下的稳定回归集。
