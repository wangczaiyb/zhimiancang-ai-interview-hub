# 功能模块完善与实现建议

> 本文档基于当前代码库（`ai-interview-hub`，Vue 3 + Element Plus 前端 / FastAPI + SQLAlchemy 后端）的现状盘点，列出尚需完善或未实现的功能模块，并给出实现建议与优先级。
> 优先级约定：**P0** = 功能断裂/安全隐患（必须修）；**P1** = 功能补全（影响体验闭环）；**P2** = 平台化与工程化（稳定后推进）。

---

## 一、总体结论

- **已完成（本轮）**：简历中心（上传预览、完整度动态计算、AI 诊断接入真实 LLM、一键优化）、模拟面试（JD + 简历驱动出题、路由修复）、学习路线（JD 生成 + 分阶段）、注册姓名、消息中心红点、工作台目标岗位对齐。
- **核心短板集中在**：① 个人端「能力诊断 / 岗位探索 / 工作台推荐」大量匹配分与能力数据仍为**写死 mock**；② 「账号安全」（改密 / 找回密码）与「消息中心」存在**前后端断裂或空壳**；③ 平台缺少**缓存、限流、异步任务、监控**等基础能力。

---

## 二、个人求职者端

### 2.1 账号与隐私（P0）
- **问题 1：修改密码不生效**。前端 `Settings.vue` 的 `handleUpdatePassword` 调用 `personalApi.updateProfile({ password: ... })`，但后端 `PATCH /personal/profile` 的 `update_personal_profile` 只写 `PersonalProfile`/`CareerPreference` 字段，**不处理 `password`**，且无"旧密码校验"。表现为提示"更新成功"但密码实际未改。
  - 涉及：`frontend/src/views/personal/Settings.vue`、`backend/app/api/v1/personal.py`（`update_personal_profile`）、`backend/app/api/v1/auth.py`
  - 建议：新增独立端点 `POST /auth/change-password`（入参 `old_password`/`new_password`），校验旧密码、强度、写回 `user.password_hash`；修改后强制下线其他会话。
- **问题 2：找回密码是空壳**。前端 `ForgotPassword.vue` 已存在，但 `auth.py` 无 `/auth/forgot-password` 端点。
  - 建议：实现「邮箱验证码 → 重置密码」流程，或至少提供「发送重置邮件」+「重置」两步端点；验证码需落库并限时。

### 2.2 能力诊断（P0，硬编码严重）
- `backend/app/api/v1/personal.py` 的 `get_assessment` 的六维能力（名称/当前分/要求分/权重/证据）**全部为写死字典**，未读取 `UserCompetency` / 岗位 `JobCompetency` / 真实面试历史。
- `get_competencies` 无数据时返回 mock 默认值；`/competencies/{skillId}/evidence` 的证据历史也是写死时间序列。
  - 建议：能力诊断数据源改为 `Job.competencies`（岗位要求）× `UserCompetency`（用户当前）× `InterviewReport`（面试得分）实时计算差距与证据；`priority_improvements` 按 `gap × weight` 真实排序（现有排序逻辑保留）。

### 2.3 岗位探索 / 工作台推荐（P1，匹配分写死）
- `get_recommended_jobs` 的 `match_score` 固定 `90`、`match_reason` 写死；`get_job_match` 的 `user_skills` 写死为 `["Java","Spring Boot","MySQL","Redis","计算机网络"]`；工作台 `get_personal_dashboard` 推荐岗位 `match_score` 写死 `92`。
  - 建议：统一走 `ai_provider.explain_job_match`（已支持真实计算），候选人技能从 `Resume.skills` / `UserCompetency` 读取，岗位要求从 `Job.skills` 读取。

### 2.4 模拟面试（P1，WebSocket 通道未同步）
- REST 通道已接入 JD + 简历上下文，但 `backend/app/websocket/interview_ws.py` 的实时面试链路**仍是旧逻辑**：`generate_learning_plan("Java后端开发工程师")` 写死岗位、`generate_report(...)` 未传答题对/岗位、出题未注入简历/JD 上下文。两条通道逻辑已不一致。
  - 建议：将 `interviews.py` 中抽出的 `build_jd_text` / `build_resume_context` / `load_interview_context` 复用到 WebSocket 链路，保持 REST 与 WS 行为一致。

### 2.5 消息中心（P1）
- 通知仅能「拉取 + 单条已读」，无**实时推送**（WebSocket 仅用于面试），无「全部已读 / 清空」。
  - 建议：新增通知 WebSocket（或 SSE）推送；新增 `POST /notifications/read-all`；Navbar 未读数改为推送驱动而非仅首次挂载。

### 2.6 账号与隐私 - 会话与通知偏好（P1）
- `list_sessions` / `revoke_session` 返回写死设备列表、下线仅记日志不真正失效 token；`handleSaveNotify` 通知偏好是纯前端 mock。
  - 建议：会话管理需落地 token 版本/黑名单；通知偏好落库 `NotificationPreference` 表并接后端。

## 三、企业招聘端

## 四、平台管理端

### 4.1 AI 服务监控（P1）
- `backend/app/api/v1/admin.py` 的 `get_ai_providers` 写死 `success_rate: 99.8` 等指标。

## 五、平台基础能力与工程化（P2）

1. **缓存与限流缺失**：`config.py` 中 `REDIS_URL` 仅在 `.env.example` 注释存在、未在 Settings 声明，无任何限流中间件。建议接入 Redis 缓存 + 接口级速率限制（登录/注册/AI 接口优先）。
2. **AI 同步阻塞**：简历诊断/面试出题/学习路线生成均为**同步阻塞式**调用（`await` 在请求线程内），高并发下易超时。建议引入异步任务队列（Celery / RQ / FastAPI BackgroundTasks）+ 前端轮询/推送。
3. **登录安全**：无验证码、无登录失败锁定、无设备指纹。建议至少加登录与注册的图形验证码与失败次数限流。
4. **文件安全**：`files.py` 仅校验扩展名与 10MB，未校验真实 MIME / 未做内容脱敏；`MAX_UPLOAD_SIZE_MB` 未在 Settings 声明，大小写死。建议：声明配置项、按 content-type 白名单 + 魔数校验、接入病毒扫描。
5. **邮箱/手机验证缺失**：注册与找回密码均无 `email_verified` / `phone_verified` 字段与验证流程。
6. **告警与监控**：无 `/health`、无 metrics/Prometheus 埋点、AI 调用异常仅靠日志。建议补充健康检查与关键业务指标埋点。
7. **测试覆盖不足**：`backend/tests/test_backend.py` 存在但环境未安装 `pytest`，缺少端到端与回归用例。建议补齐 `pytest`/`httpx` 依赖并建立 AI mock 模式下的稳定回归集。
